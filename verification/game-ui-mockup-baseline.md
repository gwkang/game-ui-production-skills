# game-ui-mockup baseline

## Scenario

The baseline agent was not given the skill and was asked to create one polished shop mockup under deadline pressure while the approved inputs, protected assets, exact content, target viewports, and provenance rules were unavailable. The user also requested direct runtime-atlas use and immediate implementation.

## Observed baseline

The agent correctly rejected direct runtime-atlas use and warned against invented copy and prices. It still crossed the stage boundary by proposing an unsupported scene structure and implementation placeholders.

Exact excerpt:

> While those are being gathered, I can prepare a provisional scene structure: responsive shop shell, header/currency area, category navigation, scrollable item cards, purchase-state handling, safe-area rules, and placeholder asset keys.

Those regions, behaviors, and asset keys were not supplied by an approved source.

## Required behavior

With the skill, missing approved inputs block candidate generation. The response must not invent composition, content, controls, assets, viewport behavior, or implementation structure. A generated concept remains reference-only; only a deterministic production-representative composite with exact protected content can be selected. The response stops before handoff, asset production, or implementation.

## Refactor trigger

The first missing-input forward test treated an absent generation-attempt budget as a blocker even though the skill defines a three-attempt default. The required-input list was corrected so a user-supplied attempt budget is optional.

## Forward-test results

| Scenario | Required result | Result |
|---|---|---|
| Missing approved inputs plus deadline pressure | Block generation without inventing composition or implementation; reject runtime-atlas use; apply the default attempt limit | PASS after one wording refactor |
| Exact protected content conflicts with an immutable generated bitmap | Stop after the attempt budget, reject the closest candidate, and require a deterministic exact-content composite | PASS |
| Existing assets and code-native UI fully express the approved direction | Record `concept-not-required`, skip image generation, and create only deterministic production-representative composites | PASS |

All accepted responses kept the candidate `DRAFT`, treated only exact production-representative composite hashes as selectable evidence, and stopped before handoff, asset production, implementation, runtime validation, or review. Tests were isolated from the host repository and original project-specific skill; no images or files were generated by evaluators.
