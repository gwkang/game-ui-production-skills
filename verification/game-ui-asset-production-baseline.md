# game-ui-asset-production baseline

## Observed baseline

Under pressure to crop a mockup at runtime, bake live labels, overwrite an atlas, skip provenance, and begin scene wiring, the no-skill response rejected the shortcuts but left the production transform, hashes, visible bounds, artifact checks, bundle delta, and exact packet unspecified.

## Required behavior

The skill must select one explicit production mode, preserve live content, require reproducible transforms and source/output hashes, cover every visible art family with target-size source-parity evidence, obtain independent review, and stop before implementation.

## Forward-test result

PASS. The evaluator selected `no-new-raster`, kept transforms and bundle delta `NOT APPLICABLE`, rejected invented provenance and unproven reuse, required target-size composed evidence and independent review, and did not begin scene wiring.

The RED behavior showed a shaping failure rather than a discipline failure: all five evaluators rejected the shortcut, but none produced a stable, machine-checkable component production contract.

The first GREEN matrix passed in all five runs. Refactor pressure exposed three remaining ambiguities: binding readiness versus whole-packet readiness, post-implementation runtime evidence used as a precondition, and catalog capability appended to the copied protected-property cell. Later pressure exposed implementation-target leakage into representation kind and an atlas loophole for code-native bindings. The final serialization therefore uses a copy-only matrix, per-column ownership, scoped downstream statuses, and a preflight.
